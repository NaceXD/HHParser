# 💼 Агрегатор вакансий HeadHunter (HHParser)

Современный асинхронный веб-сервис для автоматического сбора, умного локального хранения и фильтрации вакансий с платформы **hh.ru**. Проект спроектирован с упором на высокую отказоустойчивость, безопасность многопоточной работы с СУБД SQLite и соблюдение стандартов «вежливого скрейпинга» (polite scraping).

---

## 🛠️ Технологический стек (Tech Stack)

* **Backend:** [Python 3.14.3](https://python.org) + [FastAPI](https://tiangolo.com) (высокопроизводительный асинхронный веб-фреймворк)
* **Scraping Engine:** [lxml](https://lxml.de) + [XPath](https://w3.org) (быстрый разбор DOM-дерева в обход ограничений нативных JS-движков)
* **Network Layer:** [httpx2](https://github.com) / `httpx` (асинхронный HTTP-клиент с поддержкой устойчивых сессий)
* **Database & Migrations:** [SQLAlchemy 2.x](https://sqlalchemy.org) (ORM-слой) + [Alembic](https://sqlalchemy.org) (управление миграциями схем данных)
* **Database Engine:** [SQLite](https://sqlite.org) (режим **WAL** — Write-Ahead Logging, расширенный конкурентный пул соединений)
* **Validation Layer:** [Pydantic v2](https://pydantic.dev) (строгая валидация данных через типы и конфигурации `ConfigDict`)
* **Logging:** Модуль `logging` (потокобезопасная раздельная ротация логов в терминал и файл `parser.log`)

---

## 🏗️ Архитектурные особенности проекта

1. **Многопоточный асинхронный конвейер (`Crawler + Hydrator`)**: Процесс разделен на две параллельные стадии, контролируемые Event Loop:
   * **Crawler** собирает базовые карточки (скелеты) вакансий из поисковой выдачи.
   * **Hydrator** извлекает детальную информацию (зарплаты, даты публикации, навыки) из внутренних страниц вакансий.
2. **Потокобезопасный пул соединений БД**: Для интеграции асинхронных корутин с синхронным ORM-слоем SQLAlchemy транзакции изолированы внутри системных потоков (`asyncio.to_thread`). Каждая сессия `SessionLocal` порождается и гарантированно уничтожается в границах своего потока, полностью исключая гонки данных.
3. **Безопасный `UPSERT` и Many-to-Many**: Логика обновления записей защищает базу от перезаписи полезных полей пустыми значениями при повторном сканировании. Связи Many-to-Many со справочником уникальных навыков обновляются атомарно и только при фактическом наличии новых тегов.
4. **Управление жизненным циклом фоновых задач**: В отличие от стандартных фоновых queues, конвейер регистрирует выполняемые процессы в реестре `ACTIVE_TASKS` в виде полноценных объектов `asyncio.Task`. Это дает возможность гарантированно отменять и прерывать бесконечные циклы сбора данных в роутах по команде пользователя с корректной обработкой `asyncio.CancelledError`.
5. **Абсолютное позиционирование окружения**: Пути к лог-файлам и файлу базы данных `hh_vacancies.db` динамически рассчитываются через класс `Path`, что предотвращает дублирование и замусоривание системы при запуске проекта из разных рабочих директорий.

## ⚡ Быстрый запуск и развёртывание

### 1. Подготовка окружения и зависимостей
Убедитесь, что у вас установлен Python версии **3.14.3**. Склонируйте репозиторий, перейдите в корень проекта, создайте и активируйте виртуальное окружение:

```bash
git clone https://github.com
cd HHParser
python -m venv .venv

# Для Windows (CMD / PowerShell):
.venv\Scripts\activate
# Для macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

### 2. Настройка конфигурационного файла
Создайте в корне проекта файл **`.env`** (на основе `.env.example`) и заполните базовые параметры:
```env
USER_AGENT="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"
```

### 3. Применение миграций базы данных
Перед первым запуском разверните актуальную структуру таблиц в SQLite через Alembic:
```bash
alembic upgrade head
```

### 4. Запуск веб-сервера
Запустите сервер разработки Uvicorn, указав путь к приложению внутри пакета `src`:
```bash
uvicorn src.main:app --reload
```

После этого приложение будет доступно по адресам:
* **Интерактивная документация API (Swagger):** [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
* **Проверка статуса парсера:** [http://127.0.0.1:8000/api/parser/status](http://127.0.0.1:8000/api/parser/status)

## 📡 Спецификация API-эндпоинтов

### `GET /api/parser/status`
Возвращает текущий операционный статус и метрики сессии фонового парсера (количество отсканированных страниц, найденных вакансий, флаг встречи капчи и описание ошибок).

### `GET /api/vacancies`
Возвращает список детально обработанных вакансий из базы данных с предзагруженными навыками (стратегия `joinedload`).
* **Параметры:**
  * `search` (str, необязательный) — Регистронезависимый поиск по подстроке.
  * `limit` (int, необязательный) — Ограничение количества строк. По умолчанию возвращает последние 20 вакансий.

### `POST /api/parser/start`
Инициализирует и запускает асинхронный фоновый конвейер сбора вакансий по переданному ключевому слову. Изменяет статус на `"running"`.
* **Параметры (Query):**
  * `search_text` (str, обязательный) — Ключевое слово для поиска на HeadHunter (например, `Python`).

### `POST /api/parser/stop`
Принудительно останавливает активные задачи краулера и гидратора, вызывая метод `.cancel()` на объектах `asyncio.Task`. Переводит статус в `"stopped"`.

### `GET /api/vacancies/export/exel`
Выгружает отфильтрованный или полный срез вакансий из базы данных и отдает клиенту сформированный в памяти файл Excel (в виде бинарного потока `io.BytesIO`).
